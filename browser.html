DEEP DIVE

Browser use

A browser agent often does not need a large model to write a paragraph at every step. Most steps are bounded decisions: what operation? and which observed element?

Real example: Browser Use's public jev-ultrafast demo reports Zürich → London in Google Flights in 7.1s. Jev chooses an operation and target; a small text model is invoked only when text actually has to be generated.

while not done:
  state = browser.observe_visible_controls()

  decision = jev.ask(state, {
    operation: Choice([CLICK, TYPE_TEXT, SELECT, DONE]),
    click_target: Choice(clickable_elements),
    type_target: Choice(editable_elements)
  })

  if decision.operation == TYPE_TEXT:
      value = small_text_model(goal, field)
      browser.type(decision.type_target, value)
  else:
      browser.execute(decision.operation, compatible_target)

  # independently verify the outcome; choosing DONE is not proof.

Why this composition is interesting

Dynamic action space

The choices come from what the browser actually observed. The model does not need to invent CSS selectors, coordinates or JavaScript.

Parallel heads

Operation and operation-specific target questions can be evaluated together. Code consumes only the target compatible with the selected operation.

Generate only when necessary

Clicking and selecting are decisions. Typing an arbitrary city or message requires generation, so hand that one step to a text model.

Code owns safety

The executor can reject stale or occluded elements, constrain supported operations, prevent arbitrary code execution and independently verify success.

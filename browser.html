BROWSER USE

A browser agent is mostly a sequence of small decisions

On most browser steps, the model does not need to write anything. It needs to inspect the current page and choose a legal action: click this element, select that option, type into this field, or stop.

Public example: Browser Use's jev-ultrafast demo reports completing a Zürich → London Google Flights task in 7.1 seconds after initial page observation. Source and recording · Watch the embedded demo. The architecture is the split: Jev handles bounded action selection; a text model is used only when arbitrary text must be produced.

One browser step

Observe, don't ask the model to invent the page

The browser runtime extracts the controls it can actually interact with: buttons, links, inputs and selects. Those become the current action space.

Choose the operation

A small Choice asks whether the next move is CLICK, TYPE_TEXT, SELECT or DONE. The model returns a distribution over those known operations.

Choose a compatible target

The target is another runtime Choice over the elements observed on this page. After navigation, the choices can be completely different.

Generate only if the action requires language

If the decision is “type into Destination,” Jev has selected the action and field. A generative model can supply the open-ended value such as “London.”

Execute in code and observe again

The browser runtime performs the action, rejects stale/invalid targets, then creates the next state. The loop continues until independently verified completion.

Conceptual pseudocode · not an SDK example

while not verified_done:
    page = browser.observe()

    decision = jev.ask(page, {
        operation: Choice([CLICK, TYPE_TEXT, SELECT, DONE]),
        click_target: Choice(page.clickable_elements),
        type_target: Choice(page.editable_elements),
    })

    if decision.operation == TYPE_TEXT:
        value = text_model(goal, decision.type_target)
        browser.type(decision.type_target, value)
    else:
        browser.execute(decision.operation, compatible_target)

    verified_done = verify(browser.observe(), goal)

What changes in the browser loop

Smaller output space

The decision is one of the actions the browser can really perform, not arbitrary prose, selectors or JavaScript.

Dynamic choices

The action space is rebuilt from each page. Runtime-defined Choice is a natural match for UI state that changes after every interaction.

Generation is selective

Clicking is a decision. Writing an email is generation. The architecture can use each model only for the part it is suited to.

Safety boundary

Jev choosing an action is not permission to execute it. The browser runtime can enforce domain allowlists, prevent arbitrary code execution, require confirmation for purchases, reject hidden or stale elements, and verify success independently.

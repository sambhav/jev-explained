ARCHITECTURE · STEP BY STEP

Understand the input once. Read the decisions directly.

A normal LLM first builds a rich representation of the input, then spends additional sequential work generating the answer as tokens. Jev appears to preserve the first part and replace the second with parallel probability readouts over the decisions the application asked for.

Evidence status: TypeSafe has not published the full architecture. This page separates an ordinary-LLM baseline, a public Qwen/RLCD reconstruction, and inferences from Archer Hume's black-box experiments.

1. The part both systems need: understanding the input

Take a long incident report. Whether the final answer is prose, JSON or a probability, the model first has to understand the report. In a decoder Transformer this initial pass is called prefill. Each layer attends over the prompt and builds contextual representations; reusable keys and values are stored in the KV cache.

The important point is that Jev does not avoid semantic inference. The claimed saving is primarily after the model has understood the state: don't make it spell a bounded decision out as a sequence of language tokens.

2. What a normal LLM does next

Generate the first output token

The model turns its final hidden state into logits over its vocabulary and chooses the next token.

Feed that token back in

The newly generated token becomes part of the context. The model performs another decode step to choose the next token.

Repeat until the JSON is complete

For a three-field decision, the application may only care about HIGH, true and TIER_2, but the model also generates braces, field names, quotes, punctuation and all the tokens needed to serialize those decisions.

Autoregressive means sequential: token 12 depends on token 11, so the output cannot simply be produced in one independent pass.

3. A simpler baseline already removes much of that work

The visual reconstruction you shared uses an ordinary Qwen2.5 decoder. It demonstrates that a model can be used as a decision engine without asking it to generate the full JSON.

Prefill the document and common context once

Run the expensive shared input through the Transformer and retain its KV cache.

Fork a tiny branch for each field

For risk_level, requires_review and action_tier, append only the field-specific suffix. All branches reuse the same representation of the document.

Look at the model's scores instead of generating

The ordinary LM head still emits a score for every vocabulary token. Throw almost all of those scores away and retain only the allowed outcomes for the field.

full_logits = LM_head(hidden_state)
allowed = ["HIGH", "MEDIUM", "LOW", "NONE"]
probabilities = softmax(full_logits[allowed])

# Application code creates the JSON.
risk_level = argmax(probabilities)

This is the key baseline. It gets many benefits attributed to decision models—shared prefill, parallel fields, valid output and no long decode—without requiring a fundamentally new Transformer.

4. What Jev appears to add

Archer Hume's 10,000-call black-box study suggests Jev is more purpose-built than simply masking an ordinary vocabulary head.

STRONG EVIDENCE

Shared state, isolated questions

Many questions can inspect the same state without seeing sibling questions. This matches a shared representation followed by independent branches. Server-time scaling was nearly flat across large numbers of questions in Hume's probes.

LIKELY

A pretrained causal Transformer remains underneath

Broad semantic knowledge has to come from somewhere. The evidence and TypeSafe's language around post-training make a pretrained language-model-like backbone plausible, but it is not confirmed.

STRONG EVIDENCE

Choice options interact with each other

This is more interesting than independent classification. Adding another option can change the relative odds among existing options, suggesting the model interprets the candidate set together.

That matters for dynamic action spaces. In a browser, “none of the above” only has meaning relative to the current clickable elements. In tool search, a tool's suitability can depend on what alternatives are available. Jev's Choice primitive appears designed around this listwise interpretation.

5. The likely computational shape

NORMAL LLM

Prefill + sequential decode

Understand state once, then repeatedly predict output tokens until the response is complete.

CONSTRAINED LLM

Prefill + masked logits

Reuse shared state, branch per field, read only the vocabulary logits corresponding to valid outcomes.

LIKELY JEV

Prefill + decision-native branches

Reuse shared state across isolated semantic questions, jointly interpret runtime options, and return calibrated probability distributions directly.

6. Why probabilities are important

An LLM can generate the string "confidence": 0.9, but that number is itself generated content. A decision model instead exposes the distribution produced by the decision mechanism. TypeSafe says RLCD—Reinforcement Learning for Calibrated Decisions—trains around these distributions.

If a model assigns roughly 80% probability to a large group of comparable predictions, a well-calibrated model should be correct on roughly 80% of them.

The exact RLCD algorithm is not public. Calibration therefore remains something to measure, not assume.

7. Why this is not just a fixed classifier

A conventional classifier is normally trained with a fixed set of labels. Jev receives the labels—or actions—at runtime.

# These choices did not exist when the model was trained.
action = Choice(
  state = {goal, current_page},
  options = current_clickable_elements,
  question = "Which element best advances the goal?"
)

The page can expose 37 actions now and a completely different 18 actions after the click. The model has to understand the natural-language meaning of those temporary options and compare them in the current state. That is closer to a general semantic policy over runtime-defined actions than a traditional classifier.

8. What remains unknown

Backbone

No confirmed base model, parameter count or weights.

Decision readout

Pointer-like scoring, reserved decision slots, specialized heads or another design are all possible.

RLCD

The training recipe and exact calibration objective are unpublished.

MoE

A sparse mixture-of-experts design has been hypothesized but has substantially weaker evidence.

Sources

Archer Hume — Jev's Architecture Unmasked provides the strongest public behavioral probing currently available. The Qwen/RLCD visual reconstruction demonstrates a simpler ordinary-Transformer baseline: shared prefill, field-specific branches, candidate-logit masking and softmax.

A HANDS-ON GUIDE TO JEV

How does an AI agent
choose what to do?

Read a customer message. Choose a team. Check whether a refund is justified. Jev is a model for questions like these: it returns choices and scores your software can act on.

Try the examples below to see how this works, where it saves steps, and where you still need other tools.

How would a regular LLM answer?

You could ask an LLM to generate JSON such as {"team":"checkout"}. Structured output constrains the format. The model still generates output tokens in sequence. Jev exposes a specialized interface for judgments; your program receives typed values and probabilities.

Classification and scoring have existed for years. The useful question is whether a model can handle your changing questions accurately, quickly and cheaply enough to use throughout a workflow.

Three boundaries worth remembering

A valid answer can be wrong

Selecting a real team avoids an invented team name. It does not prove the selected team is correct.

A probability needs validation

Test whether predictions near 80% are correct roughly 80% of the time on your own data.

Some work still needs generation

Writing a reply, creating code and working through a new plan remain natural jobs for generative models.

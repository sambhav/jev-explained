JEV EXPLAINED

LLMs generate. Most software needs decisions.

Jev is a model built around that distinction. Give it unstructured state and a bounded question; it returns probabilities over the possible answers instead of generating a response token by token.

The useful abstraction: Jev turns semantic understanding into something application code can use directly—an if, a switch, or a score.

The decision space is defined up front. The probability distribution is the output.

Why that matters

Semantic interpretation is everywhere in products, but historically it has been awkward to program. “Is this urgent?”, “which team owns this?”, “which search result actually answers the query?”, and “which action should the browser take?” are easy questions for a person and hard rules to write.

LLMs made those questions programmable because they understand language and context. But their interface is still generation: prompt the model, wait for tokens, constrain or validate the output, parse it, then recover the decision the application actually wanted.

Jev removes that indirection. The application declares the decision and gets a distribution it can threshold, rank, combine with deterministic facts, monitor and calibrate.

A concrete product example

A support system receives:

“Our checkout has stopped working for every customer since this morning. We launch in two hours.”

The product does not need an essay. It needs several decisions.

judgments = jev.ask(ticket, {
  urgent:   Noul("Does this require immediate attention?"),
  owner:    Choice(["checkout", "billing", "identity", "other"]),
  severity: Score(["routine", "important", "urgent", "critical"])
})

# semantic interpretation from Jev + hard facts from the product
if judgments.urgent > .90 and account.sla == "priority":
    page(judgments.owner)
else:
    queue(judgments.owner, judgments.severity)

The important boundary is explicit: Jev interprets meaning; application code decides what happens.

Why not just use an LLM?

No output-language problem

If the product needs one of four actions, arbitrary text generation is unnecessary. Jev's output space is those four actions.

Probabilities are the API

Confidence is not another sentence or field the model invents. The application receives a distribution over the bounded outcomes.

Designed for repeated decisions

Search ranking, browser control, games, routing and safety can require many small judgments. This is the workload Jev is trying to optimize.

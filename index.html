JEV EXPLAINED

Semantic decisions as a software primitive

Jev takes unstructured application state and returns typed probabilistic judgments. Instead of generating prose or JSON to represent a decision, the decision itself is the output.

A concrete example

A support system receives:

“Our checkout has stopped working for every customer since this morning. We launch in two hours.”

The product needs three judgments: whether this needs immediate attention, who owns it, and how severe it is.

TYPICAL LLM
result = llm(
  ticket,
  "Return JSON with urgent, owner, severity"
)
result = validate_and_parse(result)

A general text generator produces a representation of the decision.

JEV
urgent = Noul("Requires immediate attention?")
owner = Choice(["checkout", "billing", "identity", "other"])
severity = Score(["routine", "important", "urgent", "critical"])

The API returns the bounded judgments and their probabilities directly.

Three operations

Noul
Is X true?
Semantic if
Choice
Which X?
Semantic switch
Score
How much X?
Semantic score / sort

Jev supplies the semantic judgment. Existing code still owns permissions, policy, business rules and irreversible actions.

Why use this instead of a typical LLM?

Bounded output

If the application needs one of four actions, arbitrary text generation is unnecessary. Jev's output space is the decision space.

Probabilities are first-class

The application can threshold, rank, combine and monitor the distribution instead of extracting confidence from generated text.

Parallel judgments

Independent questions about the same state can be evaluated together rather than expressed as a sequential generated response.

Where it becomes useful

PRODUCTS

Search, routing, recommendations, safety →

Detailed architectures for search reranking, tool selection, notifications, support, inbox, commerce, CRM, forms, safety and agent control.

BROWSER

Repeated UI decisions →

Current page state plus available actions becomes a bounded decision problem. Text generation is used only where text is actually required.

GAMING

Real-time action selection →

Game state plus legal actions becomes a repeated policy decision at interactive latency.

ARCHITECTURE

How might Jev work? →

Disclosed facts, unknowns, adjacent research and a clearly labelled conceptual architecture.

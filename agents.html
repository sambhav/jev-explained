USE CASE / AN AGENT YOU CAN FOLLOW

Where decision models fit inside an agent.

An agent observes a situation, chooses an action, uses a tool and checks what changed. Jev can help with the bounded judgments inside that loop. A language model still handles open-ended planning and writing.

Walk through a customer-support agent

Follow one refund request from message to reply. Jev interprets the customer’s intent; code checks the payment record and permission. Change the scenario to see the route change, including a failed tool call.

STATE & EVIDENCE

Scripted teaching example. No model or payment system is called.

What goes where?

JEV: BOUNDED JUDGMENTS
  • Which tool is relevant?
  • Does this result answer the question?
  • Does the proposed reply contradict the record?
  • Should the system seek clarification?
THE REST OF THE SYSTEM
  • LLM: make a plan and write the response.
  • Tools: retrieve authoritative facts.
  • Code: check access, limits and consent.
  • Runtime: retry, log and verify tool outcomes.

Independent judgments over one observation can share a request. A judgment that depends on the result of a tool call must wait for that result. Parallel answers do not make an entire agent workflow parallel.

Request dependencies

Which questions can run together?

A customer asks about a charge. Choose questions about the message and the payment team’s investigation note. Then change when the note becomes available. Counting requests helps explain dependencies; it does not predict latency.

Questions to ask
When is the investigation note available?

This diagram counts model request rounds, not seconds. Questions in one Jev request share the same state and cannot use each other’s answers. A tool call can add delay even when it requires no model request. Documented behavior ↗

For a PM, this changes what to measure: successful resolutions, time to resolution, cost per resolved case and the rate of unnecessary escalations. A faster judgment helps only if the rest of the workflow can use it.

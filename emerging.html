Context selection and language experiments

These are optional extensions of the same interface. Start with the agent walkthrough if the distinction between a judgment, an application rule and a tool call is still unclear.

The two linked projects below illustrate implemented approaches. Their pseudocode here explains the idea and is not a copy of either project’s API.

CONTEXT COMPACTION

Select which original context to keep

Traditional agent compaction asks an LLM to rewrite old context into a summary. That saves tokens, but exact paths, errors, constraints and tool outputs can disappear. fast-jev-compaction takes a different approach: keep the original conversation verbatim and ask Jev which tool calls/results are still worth retaining.

Full transcriptOriginal messages and tool history
Parallel NoulsKeep this call? Keep this result verbatim?
Code thresholdsKeep · truncate · remove
Compact contextSurviving content remains verbatim

Conceptual pseudocode · not an SDK example

for pair in older_tool_call_result_pairs:
    # Both questions see the task, conversation and this specific pair.
    scores = ask(state={current_task, conversation, pair}, questions={
        keep_call: "Does knowing this call still matter?",
        keep_result: "Is its exact result still needed?"
    })
    if scores.keep_result >= threshold:
        retain(pair)
    elif scores.keep_call >= threshold:
        retain(pair.call, truncate(pair.result))
    else:
        remove(pair)
# Preserve required call/result pairing and always keep pinned instructions.

The model scores what to retain; code removes the rest. Jev can judge many old tool calls against the same conversation state in parallel. The published plugin pins recent messages, batches questions under the request limit, and falls back to ordinary summarization if pruning is insufficient.

Public project: tamaratran/fast-jev-compaction. Its README documents the keep/truncate/drop algorithm and fallback behavior.

Failure to watch for: an old error or constraint may become relevant later. Measure lost facts and task completion, not just the number of tokens removed.

PROBABLY · SEMANTIC PROGRAMMING LANGUAGE

Use a model judgment inside an if statement

Steve Faulkner's Probably takes the “AI if statement” literally. Instead of calling Jev through an SDK and then branching on the result, the language makes fuzzy semantic judgment part of its syntax. The example shared publicly uses feels as a semantic predicate and match to route between natural-language descriptions.

Conceptual pseudocode · not an SDK example

let email = input()

if email feels "urgent" {
    print(llm "Draft a reply" using email)
}

A conventional if evaluates a boolean expression whose semantics are completely specified by code. A semantic if evaluates a proposition against unstructured state. The runtime can compile that predicate into a Jev Noul, apply a threshold, then execute the branch normally.

Source codeemail feels "urgent"
Compiler/runtimeRecognize semantic predicate
JevP(urgent | email)
Normal control flowTake or skip branch

The branch now depends on a model judgment. Arithmetic, loops, types and effects stay conventional; interpretation of human concepts becomes another expression the runtime can evaluate.

Project reference: Probably. Syntax shown here is illustrative; check the project for its current language and runtime.

Examples beyond ticket routing

These examples reuse the three outputs introduced in the basics chapter. Each starts with data the application already has, asks a bounded question, then uses the answer in code.

Search: rank a small set of retrieved documents

Input: a search query and 50 candidate documents. Question: how well does each document answer the query? Output: one Score per document. Code sorts the results.

Conceptual pseudocode; independent scoring requests may run concurrently.

hits = search.retrieve(query, top=50)
for hit in hits:
    hit.relevance = score(
        state={query, hit.text},
        rubric=["irrelevant", "weak", "useful", "direct answer"]
    )
return sorted(hits, key=relevance, descending=True)

The model scores only the candidates. It cannot recover an important document the retrieval step missed. Compare ranking quality and added latency against your existing reranker.

Tool selection: choose from permitted candidates

Input: a user goal and descriptions of tools the agent may use. Question: which tool fits the goal? Output: a Choice, including a “none fit” option. Selecting a tool does not supply its arguments or execute it.

Conceptual pseudocode; argument construction is a separate step.

tools = retrieve_tools(goal, permitted_tools, top=20)
choice = choose(state={goal, tools}, options=tools + ["none fit"])
if choice == "none fit":
    ask_for_clarification()
else:
    arguments = build_arguments(goal, choice.schema)
    validate_and_authorize(choice, arguments)
    result = execute(choice, arguments)

Measure completed tasks as well as selection accuracy. A plausible tool can still be the wrong tool, and valid arguments can still describe an unwanted action.

Notifications: judge relevance, then apply delivery rules

Input: an event and the user’s stated priorities. Question: is this relevant enough to interrupt them? Output: a Noul value. Quiet hours and rate limits are application rules.

Conceptual pseudocode; the threshold is illustrative.

relevance = judge(state={event, user_priorities},
                  question="Does this need the user's attention now?")
if relevance >= 0.9 and delivery_policy.allows(event, user):
    notify(user, event)

Evaluate missed important events and unnecessary interruptions. A higher threshold trades fewer interruptions for more missed events.
